# 0017. AWS: account access, state bucket and managed services

- **Status:** Accepted (approved 2026-10-25, after the T5 close). The paid session may still supersede parts of it.
- **Date:** 2026-10-25

## Context
- T5 writes an AWS version of the platform in `terraform/aws/`. The free part has to pass `validate`, `tflint`, `trivy config` and `plan`. The paid part is optional: apply, deploy, destroy in one session. `plan` needs real AWS credentials.
- The kind setup runs Postgres, Redis and OpenSearch in the cluster. On AWS each has a managed service; the chart already has the switch pattern for OpenSearch (`opensearch.enabled: false` + `searchService.opensearchUrl`, K7 note).
- Facts checked on 2026-10-25:
  - Terraform Registry: `hashicorp/aws` 6.70.0, `terraform-aws-modules/vpc/aws` 6.7.3, `terraform-aws-modules/eks/aws` 21.29.0.
  - EKS standard support: Kubernetes 1.34–1.37; 1.37 is the default (`aws eks describe-cluster-versions`).
  - Amazon OpenSearch Service supports up to OpenSearch 3.7 (we run 3.9 locally; search-service uses opensearch-go v5, ADR-0005). T3 instances support encryption at rest but not Auto-Tune.
  - RDS offers PostgreSQL 18.6 on `db.t4g.micro`. ElastiCache offers Valkey up to 9.1; Valkey nodes are about 20% cheaper than Redis OSS (cache.t4g.micro: USD 0.0128/h vs 0.016/h), and AWS's Redis OSS engine stops at 7.x.
  - EKS 1.28+ envelope-encrypts all Kubernetes API data with an AWS-owned key by default, at no cost.
  - The account had no OpenSearch service-linked role (only the console creates it automatically).
  - The first two AWS Budgets are free.
  - Price List API, us-east-1 on-demand: the stack costs about USD 0.31/h, plus about 0.04/h for the app's load balancer and its IPs once deployed.

## Options
1. **Credentials:** IAM Identity Center (SSO) profile (chosen); IAM user access keys; no account (offline checks only).
2. **Permissions for that user:** `AdministratorAccess` permission set (chosen); a custom least-privilege policy.
3. **Region:** us-east-1 (chosen); eu-central-1; me-central-1.
4. **OpenSearch:** Amazon OpenSearch Service (chosen); keep it in the cluster (needs the EBS CSI driver add-on, its IAM role and bigger nodes).
5. **Cache engine:** ElastiCache for Valkey (chosen); Redis OSS.
6. **State for `terraform/aws/`:** a real S3 bucket (chosen); the MinIO backend from ADR-0016; local state.
7. **State for the bootstrap root that creates that bucket:** migrated into the bucket itself (chosen); local and git-ignored; MinIO.
8. **Budget alert:** created by the bootstrap root (chosen); by hand in the console.
9. **EKS API endpoint:** public but limited to the user's IP (chosen); public to all; private only (needs a bastion or VPN).
10. **Nodes:** 2× t3.medium on-demand (chosen); the same on Spot; 2× t4g.medium Graviton (needs multi-arch images).
11. **OpenSearch authentication:** network only, an open access policy behind a security group (chosen); fine-grained access control with basic auth; IAM request signing. Both alternatives need app changes.
12. **RDS master password:** generated by RDS and kept in Secrets Manager (chosen); `random_password` in Terraform state.

## Decision
- **Access:** an SSO user with the `AdministratorAccess` permission set and short sessions, used through the profile `catalog-aws` (`aws configure sso`, then `aws sso login --profile catalog-aws`). No long-lived keys on disk. The providers set `allowed_account_ids`, so a wrong profile fails before any API call changes anything.
- **Region:** us-east-1 for everything.
- **Two roots:**
  - `terraform/aws/bootstrap/`: the state bucket and the budget. Applied once with local state, then `terraform init -migrate-state` moves its own state into the bucket it created (key `product-catalog/aws-bootstrap/terraform.tfstate`).
  - `terraform/aws/infra/`: VPC, EKS, ECR, RDS, ElastiCache, OpenSearch. State key `product-catalog/aws/terraform.tfstate` in the same bucket.
- **State bucket** `product-catalog-tfstate-<account ID>`: versioning, default encryption (SSE-S3), Block Public Access on all four settings, owner-enforced object ownership, a policy that denies non-TLS requests, and a lifecycle rule that deletes old versions after 90 days (as in MinIO). Locking with `use_lockfile = true`, as in ADR-0016. No `force_destroy`: Terraform can't delete it while it holds state.
- **Budget:** USD 10 a month, emailing at 50% and 100% of actual spend and 100% of forecast. The email address lives in a git-ignored `terraform.tfvars`.
- **Network:** `10.0.0.0/16` over us-east-1a and 1b; private subnets `/19` (the VPC CNI gives each pod a VPC IP), public `/24`, database `/24` with their own route table and no route out. One shared NAT gateway.
- **EKS 1.37** with a managed node group of 2× t3.medium (AL2023, on-demand). The public endpoint accepts only `admin_cidrs`; access entries only (`authentication_mode = "API"`), with the identity that runs Terraform as cluster admin. Add-ons: vpc-cni, eks-pod-identity-agent, coredns, kube-proxy, metrics-server. No customer-managed KMS key (EKS's default encryption), no IRSA (Pod Identity if needed), all five control-plane log types kept 1 day.
- **Managed services,** each in the database subnets with a security group that admits only the EKS node security group:
  - RDS PostgreSQL 18 (minor version chosen by RDS) on `db.t4g.micro`, 20 GB gp3, encrypted, single-AZ, password managed by RDS in Secrets Manager.
  - ElastiCache for Valkey 9.1 on one `cache.t4g.micro`, encrypted at rest and in transit (TLS).
  - OpenSearch Service 3.7 on one `t3.small.search` with 10 GB gp3, inside the VPC, HTTPS only, encrypted at rest and between nodes, with an access policy that allows any request that reaches it.
  - ECR repositories for the three images, with immutable tags, a scan on push, and the 10 newest images kept.
- **Teardown in one session:** RDS without deletion protection or a final snapshot, ECR with `force_delete`.
- **Checks:** `trivy` findings are fixed or ignored in the file with a reason (`#trivy:ignore:<ID>`), and an ignore that doesn't match a finding is removed.

## Consequences
- Applying the bootstrap root creates real AWS resources. Their cost is close to zero (one small versioned bucket, free budgets), but it's an apply against a real account, so it needs the user's go-ahead.
- Destroying the bootstrap root takes three steps: migrate its state back to local (remove `backend.tf`, `init -migrate-state`), empty the bucket including old versions, then `destroy`. The awkward order is the price of keeping the state in the bucket.
- The account ID appears in the bucket name, and `backend.tf` holds the bucket name as a literal, so the public repo shows the account ID. AWS doesn't treat account IDs as secret. If that matters later, move the bucket name to a git-ignored partial backend config (`-backend-config=backend.hcl`).
- `AdministratorAccess` is broad. It's acceptable for a personal account with MFA and short sessions; a team would run Terraform through a narrower role, ideally from CI.
- Local (3.9) and AWS (3.7) OpenSearch differ by two minor versions, and local Redis 8 vs Valkey (Redis 7.2-compatible) by a major one. catalog-api only uses basic key commands, and search-service a basic mapping, so neither is expected to matter; the paid part would confirm it.
- Managed services mean the chart needs off-switches for Postgres and Redis too, like the one OpenSearch has. That's a chart change, made when (and if) we deploy to EKS. The app's connection strings also change: `?sslmode=require` for RDS (TLS is enforced from PostgreSQL 15), `rediss://` for Valkey, `https://<endpoint>` on port 443 for OpenSearch.
- "Network only" on OpenSearch means any pod in the cluster can read and write the index. It's acceptable for a demo; a real setup would sign requests with IAM (Pod Identity) or use fine-grained access control.
- One NAT gateway and single-AZ databases mean one AZ failure takes the app down. That's a cost choice, not a production design.
- `admin_cidrs` holds the user's home IP. When the IP changes, kubectl gets timeouts until `terraform.tfvars` is updated and applied.
