# 1.4 Wire up + Compose
- Date: 2026-10-22 · Commits: a3e4e74 · Plan: [2026-10-22-1.4-plan.md](2026-10-22-1.4-plan.md)

## What was built
- **catalog-api ↔ search-service over HTTP:**
  - `callSearchService` (`src/search/search-service-fetch.ts`) is the one place that talks to search-service. It uses Node's `fetch` with `AbortSignal.timeout`: 2s for single calls, 15s for bulk. The timeout covers the body read too, and there are no retries.
  - Error mapping:
    - a network error, DNS failure, timeout or 5xx → `SearchUnavailableError` → 503
    - any other non-2xx → `SearchServiceError` → 500, because it means our two services disagree on the contract
  - `HttpSearchIndexer` and `HttpSearchClient` replace the 1.2 stubs. `toSearchParams` drops only `undefined`, so `minPrice=0` and `inStock=false` reach search-service.
  - `SEARCH_SERVICE_URL` is now required and validated.
- **Reindex** returns `{indexed, skipped, failed:[{id,status,reason}]}`, summed across batches, with 200 even when some items fail. Only `SearchUnavailableError` becomes 503; a Postgres failure surfaces as itself. This closes the 1.2 follow-up.
- **Search DTO** rejects what search-service would reject: `q` over 200 characters, `page × size` over 10,000, `maxPrice` below `minPrice`. Users get catalog-api's own 400, documented in OpenAPI.
- **Seed** (`src/seed/`, [ADR-0006](../adr/0006-seed-ships-in-runtime-image.md)):
  - A pure, seeded generator: 10 categories with their own nouns, 30 brands, prices spread log-uniformly so every price facet has data, and about 10% out of stock.
  - It writes with `createMany(skipDuplicates)` using fixed `SEED-00001…` SKUs, then calls `POST /admin/reindex`.
  - It runs as `npm run seed` on the host, or inside the image with `docker compose run … node dist/seed/main.js`.
- **search-service:**
  - A `healthcheck` subcommand, because distroless has no curl.
  - Bulk now uses `refresh=wait_for`.
- **Compose:**
  - a one-shot `migrate` service (from the Dockerfile's `build` stage)
  - `search-service` with no host port
  - `catalog-api` with a busybox `wget` healthcheck on `/readyz`
  - `depends_on` conditions throughout
  - OpenSearch Dashboards behind `--profile dashboards`
- **Tests:**
  - catalog-api: 142 unit tests, including a real-socket test server for timeouts, refused connections and stalled bodies, and an OpenAPI contract test.
  - The e2e test runs against an in-process fake search-service and covers the outage path.
  - search-service: a new healthcheck unit test and a bulk refresh integration test.
- **Verified live (Done-when):**
  - `docker compose up --build`: all services healthy, `migrate` exited 0.
  - The seed inserted 10,000 rows and reindexed with `failed: []` in about 6s. Re-running it inserted 0, and there are still 10,000 seed rows. The in-container seed exited 0.
  - `q=phone&category=electronics&minPrice=10000` → 92 hits, with category, brand and price facets.
  - A PATCHed price showed in search: PATCH plus search took 697 ms.
  - With search-service stopped:
    - search returned 503 in 2.0s
    - POST, PATCH and DELETE returned 201, 200 and 204, each logging the failure
    - `/readyz` stayed 200
  - After a reindex, a search immediately afterwards showed the new price (after the refresh fix).
  - Image: catalog-api 469 MB, of which `@faker-js` is 3.8 MB.

## Decisions
- [ADR-0006](../adr/0006-seed-ships-in-runtime-image.md), accepted at this close: the seed ships in the runtime image, so K2 can run it as a Job.
- **The user's choices at plan time:**
  - the seed goes in the image
  - search-service gets a `healthcheck` subcommand
  - migrations run as a one-shot Compose service
- **Bulk waits for refresh** (Finding A, below). Considered:
  - forcing `refresh=true` per batch
  - refreshing once after the last batch (which needs a new parameter or endpoint)
  - an alias-swap reindex

  Kept `wait_for` for 1.4, because the 1.5 alias-swap reindex replaces it anyway. Cost: reindexing 10k products takes about 21s instead of about 1s. This reverses 1.3's "bulk without refresh".
- **The migrate service runs from the `build` stage** (a 1.3 GB image, running as root). Considered:
  - a slim migrate stage, which is K3's exercise (ADR-0003)
  - running from the host, which a fresh clone would miss
  - an `npx prisma@7.10.1` container

  Kept, because it's local-only and leaves the K3 decision open.
- **catalog-api waits for search-service to be `service_healthy`,** kept against a reviewer suggestion. A throwaway Compose test showed that `service_started` and `required: false` don't help: an unhealthy OpenSearch aborts the whole chain. Dropping the dependency would let catalog-api take unindexed writes on every cold start. ADR-0001's promise covers runtime outages, which were verified.
- **e2e uses a fake search-service,** so tests never write `catalog_test` products into the dev index.
- **search-service publishes no host port in Compose.** It's internal only, like a ClusterIP Service.

## Review findings and corrections
- **The Done-when check found a bug** (AI-run, user decision). Right after `POST /admin/reindex`, a search cached pre-reindex results for 60s. OpenSearch had the new price, but catalog-api served the old one.
  - Cause: reindex bumps the search-cache version, but bulk didn't wait for a refresh.
  - The user chose "bulk waits for refresh". `TestBulkIsSearchableOnReturn` went red, then green, and the live re-check passed.
- **The Done-when check found a gap,** deferred by the user to 1.5: reindex only upserts. A product deleted while search-service was down stays searchable, and 30 orphan 1.3 sample docs were still in the dev index.
- **The user approved deleting the 31 orphan index docs.** They were checked to be absent from Postgres first. The index then matched Postgres: 10,002 docs.
- **The user reported, mid-build, that port 8080 is taken on their machine.** Compose isn't affected because search-service has no host port. AGENTS.md now says to use `$env:PORT='8081'` for native runs.
- **The user asked for alternatives** to the per-batch refresh and the migrate service, compared them, and kept both (see Decisions).
- **The fresh whole-branch review** (opus) said "ready to merge". Its findings:
  - It listed the missing OpenAPI 400s for search and the reindex 500 as Minor. They were re-graded Important, because Swagger is the contract (`.claude/rules/services.md`), and fixed test-first.
  - Its suggested `depends_on` fix was tested and shown not to work, so it was kept (see Decisions).
  - The in-container seed had never been run; it was run and passed.
- **The AI caught its own mistakes:**
  - Task 5 left two `tsc` errors that ts-jest doesn't report. They were fixed in their own commit, and `tsc --noEmit` was added to every later task.
  - `instanceof TypeError` fails for fetch errors under Jest's VM realm, so errors are matched by name.
  - Prettier had rewrapped four files the task didn't touch; the AI reverted them.
- **Process:** per-task commits were made on branch `1.4-wire-up` and squashed into one commit on `main`, as `close-milestone` requires.

## Follow-ups
- **1.5:**
  - **Alias-swap reindex.** Build `products-<n>` with refresh off, bulk-load it, refresh once, swap the `products` alias, then drop the old index. This removes ghost docs and replaces the 21s per-batch refresh.
  - **README:** the Compose run, the seed, Dashboards, and the port 8080 note.
  - **Deferred minors from the review:**
    - An empty bulk response is treated as "indexed 0" instead of an error (`http-search.ts`).
    - The seed parses the reindex body before checking `res.ok`, and logs "fetch failed" without the cause or URL.
    - AGENTS.md wording: "on this machine" is machine-specific; nothing warns that `start:dev` clashes with Compose on port 3000; nothing says `.env`'s `SEARCH_SERVICE_URL` reaches nothing when you run against the Compose stack.
- **K2:** run the seed as a Job with the catalog-api image and `command: ["node", "dist/seed/main.js"]`, plus `DATABASE_URL` and `CATALOG_API_URL`.
- **K3:** the migration image. Compose's `migrate` service shows the Job's shape, but its 1.3 GB root image isn't the answer.
- **K3/K6:** a 21s reindex outlasts catalog-api's 10s graceful shutdown, so a rollout mid-reindex cuts it short (re-run it). Compose's `depends_on` has no Kubernetes equivalent; readiness and restarts take over.
- **Dev data:** two leftovers from the outage drill are still in Postgres:
  - "Drill Outage Phone"
  - `SEED-03097`, whose price is now 99900; re-seeding won't reset it, because existing SKUs are skipped
- **The user's local `.env`** needs `SEARCH_SERVICE_URL`. `start:dev` refuses to start without it.
