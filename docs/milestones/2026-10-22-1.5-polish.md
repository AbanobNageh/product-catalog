## What was built
- **Alias-swap reindex that keeps taking writes** ([ADR-0007](../adr/0007-alias-swap-reindex-with-live-writes.md)):
  - search-service, `internal/index/build.go`, the build lifecycle:
    - `StartBuild` creates `products-v<n>` with refresh off, `gc_deletes: 10m`, and the `products-build` alias with `is_write_index: true`, so a racing start fails atomically and returns 409.
    - A build older than 10 minutes is taken over.
    - After a successful create, the sweep deletes alias-less `products-v<n>` indices, so build names are never reused.
    - `FinishBuild` swaps `products` in one guarded `_aliases` call (`must_exist`). The swap is its commit point: later cleanup errors are only logged.
    - `AbortBuild` is a single guarded alias remove.
  - search-service, `internal/indexer/indexer.go`, writes:
    - Each upsert or delete goes to the build alias first (1s, no refresh), then to live (`wait_for`, on `context.WithoutCancel`, 2s).
    - A failed build write aborts the build, but never fails the user's write.
    - Deletes are versioned (`external_gte`).
    - `BulkBuild` writes to the build by its concrete name.
  - search-service, other changes:
    - `internal/index/guard.go`: at startup, a versioned-delete probe refuses to run on a cluster that would auto-create `products*` indices. Compose sets `action.auto_create_index: "-products*,+*"`.
    - Endpoints `POST /reindex/start | _bulk | finish | abort`, and `DELETE /products/{id}?version=` (required).
    - `slog.SetDefault`, so the index package's logs are JSON.
  - catalog-api:
    - A `SearchReindexer` port and HTTP adapter.
    - `ProductsService.reindex` runs start → bulk batches → finish, or aborts if any item failed. It maps errors to 409 ("already running" / "aborted or replaced"), 503 and 500, bumps the search-cache version on every path, and returns `swapped`.
    - `remove` sends `version = max(now, updatedAt + 1)`.
    - OpenAPI documents 409 and `swapped`, and says a 503 may follow a completed swap, so rerunning is safe.
- **Seed:** checks `res.ok` before parsing, logs the URL and cause when catalog-api is unreachable, and exits 1 when the reindex doesn't swap.
- **Images** `catalog-api:0.1.0` and `search-service:0.1.0` (Compose `image:` tags).
- **Tests:**
  - search-service: unit tests, including a recording fake OpenSearch that pins the build-then-live write order. Integration tests against real OpenSearch for every lifecycle path, the dual-write races, concurrent starts, and a stale bulk into a replaced build. Test indices are now `products-it-<hex>`.
  - catalog-api: 167 unit tests; the e2e fake keeps the build state.
- **Verified live (Done-when), 2026-10-22, on the rebuilt `0.1.0` stack:**
  - **CRUD during a reindex.** search-service's request log puts a PATCH (44.882) and a DELETE (45.455) between `/reindex/start` (44.730) and `/reindex/finish` (45.456), and a POST (10.279) between 09.951 and 10.611 in a second run. After the swap, search showed the new price (777777), the deleted product was gone, and the created one was findable.
  - **Outage ghost:** a product deleted while search-service was stopped was still searchable, and was gone after the reindex.
  - **Speed:** a reindex of 10,002 products took **1.16s** (it was ~21s), with `swapped: true` and `failed: []`. The old index and the leftover smoke-test index were removed.
  - `TestVersionedDeleteBlocksStaleBulkDuringBuild` passes against Compose OpenSearch.
  - `docker compose up --build`: `catalog-api:0.1.0` and `search-service:0.1.0` came up healthy, and `migrate` exited 0.
  - Two simultaneous `/admin/reindex` calls gave one 200 and one 409.
  - `npm run seed` exited 0 with `swapped: true`.
  - All suites green: Go unit + integration, vet, gofmt; catalog-api unit, tsc, e2e.

## Decisions
- [ADR-0007](../adr/0007-alias-swap-reindex-with-live-writes.md), accepted at this close: the alias swap with dual-writes, versioned deletes, and the auto-create guard. It was amended three times during the build (see below).
- **The user's choices:**
  - The alias-swap reindex goes into 1.5, and product edits must keep working while it runs. Maintenance mode was the fallback, not needed.
  - The spike on the risky edge (a delete between a batch read and its bulk write) runs before any design is written.
  - The auto-create guard is set by infrastructure and checked by search-service. Rejected: the app changing a cluster setting, and maintenance mode.
  - **The README moves to the last step of the whole project** ([PLAN.md](../../PLAN.md)). Nothing goes to GitHub until then. 1.5's "Done when" was rewritten around the reindex.
- **AI defaults the user accepted:**
  - The guard is a probe, not a parser of settings.
  - Test indices are renamed under `products-*`.
  - `/admin/reindex` adds `swapped`, and doesn't swap if any item failed.
  - `bulkUpsert` is dropped from catalog-api.
  - `POST /products/_bulk` (the sample data) stays live-only.
- **Rulings made during the build** (from the controller's ledger), each one reviewed by the whole-branch reviewer, which agreed:
  - Abort is a guarded alias remove, and the start sweep cleans up.
  - Finish succeeds once the swap is done.
  - The live write survives cancellation, and the build write gets 1s.
  - When the abort after failed items fails, `/admin/reindex` returns 503.
  - A finish timeout after a real swap still reports 503.

## Review findings and corrections
- **The user's design review** chose live edits over maintenance mode, chose option (a) for the guard, and moved the README. In the AGENTS.md wording proposals, the user approved only the `start:dev` port-3000 warning. They kept the port-8080 note as it was and declined the `SEARCH_SERVICE_URL` note.
- **The pre-design spike** (the AI's call, the user agreed to "test it"):
  - It showed that unversioned deletes let a stale bulk copy resurrect a product, and that versioned deletes leave tombstones that block it for `gc_deletes`.
  - That turned the "risky edge" into a design requirement, plus an integration test.
- **The fresh design reviewer** (the builder check on the ADR, before any code) found three flaws. A spike confirmed the first:
  - **Versioned deletes silently auto-create a missing index, even with `require_alias`.** This led to the guard and the user's option (a).
  - **Writing live then build could lose an edit made during the swap.** The order is now build first.
  - **Lifecycle calls weren't tied to one run.** Each run is now identified by its build name, and every alias change is guarded.
- **The task reviews found:**
  - Task 2:
    - OpenSearch 3.9 can't remove an alias and the index behind it in one call, because `remove_index` is applied before alias actions. The ADR was amended so abort is a guarded alias remove.
    - Build names could be reused after an abort, letting an aborted run swap in a newer run's half-built index. Fixed with the sweep at start.
    - The finish swap didn't exclude the build itself from the indices it removes.
  - Task 3: a slow build write used up catalog-api's 2s, so the live write ran on a cancelled context and the edit reached neither index. Fixed: the live write is detached, and the build write has its own 1s budget.
- **The whole-branch review** (opus) said "with fixes", with two Important findings:
  - **A stale run's bulk batch could still land in a newer build** through the alias. Fixed: `BulkBuild` writes by concrete name.
  - **Two concurrent starts could put two indices behind the build alias.** The reviewer verified this on 3.9.0. Every later reindex would then fail with 500, and the 10-minute takeover would never run. Fixed: `is_write_index`, with `illegal_state_exception` mapped to 409.
  - It also found the sweep running before the create, and four doc/contract strings. All were fixed in one wave and re-reviewed clean.
- **The AI caught itself:**
  - Its first spike script stripped `_bulk`'s trailing newline, and it fixed that before reading the results.
  - It sent the ghost and CRUD checks without the `http://` prefix that PowerShell 5.1 requires. Nothing ran, and they were re-run.
  - In the first CRUD-during-reindex run, the POST landed after `finish`. The AI reported it and ran a second round instead of counting it.
- **Process:** subagent-driven, with 7 tasks and 14 reviews or re-reviews in total. The per-task commits on `1.5-polish` were squashed into one commit on `main`. The controller's rulings ledger fed the final review's triage of 29 deferred minor findings. 5 were fixed, and the rest are listed below.
