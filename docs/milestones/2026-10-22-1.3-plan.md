# 1.3 search-service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go search-service that owns the OpenSearch index (`products-v1` behind the alias `products`), with endpoints to index one product, delete one and bulk-index many, and a search endpoint with filters, facets and sorting. It runs against OpenSearch in Compose.

**Architecture:** One Go module in `services/search-service`. Pure packages (`config`, `catalog`, `query`) hold every decision that can be unit-tested. `osclient`, `index`, `indexer` and `searcher` are the only packages that talk to OpenSearch. `httpapi` depends only on small interfaces. Indexing logic lives in `indexer`, separate from the handlers (ADR-0001), so a Part 4 queue consumer can call it directly. The service runs natively in 1.3 and joins Compose in 1.4.

**Tech Stack (exact pins, see [ADR-0005](../adr/0005-opensearch-go-v5.md)):**
- Go **1.26** (`go 1.26` in go.mod; the installed toolchain is 1.26.4)
- `github.com/opensearch-project/opensearch-go/v5` **v5.1.1**, the only dependency
- the standard library for everything else: `net/http` with 1.22+ patterns, `log/slog`, `encoding/json`, `testing`
- images: `opensearchproject/opensearch:3.9.0` (never `latest`, which points at 2.19), `golang:1.26-alpine` (build), `gcr.io/distroless/static-debian13:nonroot` (runtime)

**Spec:** [`docs/plan/app.md`](../plan/app.md) (sections: search-service, Requirements for both services, milestone 1.3). The response contract is `SearchResult` / `ProductResponse` in [`services/catalog-api/src/search/search.ports.ts`](../../services/catalog-api/src/search/search.ports.ts) and [`product.response.ts`](../../services/catalog-api/src/products/dto/product.response.ts). Indexing contract: [ADR-0001](../adr/0001-two-services-synchronous-indexing.md).

## Global Constraints
- **Config from env vars only:**
  - `PORT` (default `8080`)
  - `OPENSEARCH_URL` (default `http://localhost:9200`)
  - `LOG_LEVEL` (`debug|info|warn|error`, default `info`)

  An invalid value fails startup with one error that lists every bad variable. No config files, no `.env` loader.
- **Logs:** JSON to stdout via `slog.NewJSONHandler(os.Stdout, …)`. No logging library.
- **Graceful shutdown:** `signal.NotifyContext` for SIGTERM/SIGINT, then `http.Server.Shutdown` with a **9s** deadline, then close the OpenSearch client. The process exits within the spec's 10s. Exit 0 on a clean drain, 1 if the deadline passes.
- **Health:** `/healthz` is liveness with no dependency checks. `/readyz` is 200 only when OpenSearch answers **and** the alias exists; otherwise 503.
- **Timeouts:** each OpenSearch call has a context deadline of **2s**; bulk gets **10s**. There are no retries anywhere, except the bounded startup wait in Task 2.
- **Errors:**
  - These map to HTTP **503**:
    - OpenSearch unreachable, timing out, 429 or 5xx → `osclient.ErrUnavailable`
    - the alias missing → `index.ErrAliasMissing`
  - Our own bad input → **400**.
  - The client disconnecting (`context.Canceled`) → log at debug, with no error response.
  - Anything else → **500**.
  - Error bodies are `{"error":"<message>"}`.
- **JSON:** HTTP JSON is camelCase and field-for-field identical to `ProductResponse`. OpenSearch documents are snake_case and add `in_stock`. `createdAt`/`updatedAt` are stored and returned as the **same strings** catalog-api sent (validated as RFC 3339). Responses are encoded with `SetEscapeHTML(false)`, so a search hit is byte-identical to `GET /products/:id` even when a name contains `&`, `<` or `>`.
- **Names:** index `products-v1`, alias `products`. Every read and write goes through the alias, and every write sets `require_alias=true`.
- **opensearch-go v5 client config:**
  - `DiscoverNodesOnStart: new(false)` and `DiscoverNodesInterval: -1`, with a comment pointing at ADR-0005. Discovery would hand back container-internal addresses the host can't reach.
  - `DisableRetry: true`. v5 retries 502/503/504 and network errors up to 6 times by default, which would break "no retries".
  - `DNSCacheRefresh: -1`, so a restarted container's new IP is picked up at once.
  - **The default router stays on.** No config field turns it off; only the process-wide `OPENSEARCH_GO_ROUTER` env var does. With discovery off, it only ever knows the seed URL, so it's harmless (ADR-0005).
- **No libraries** beyond opensearch-go: no router, no testify, no envconfig, no zerolog.
- **Commands:** every run/test/build command added → update **Commands** in `AGENTS.md` in the same task.

## Review Focus
1. **OpenSearch down or hanging during a search or write.** Expected: 503 within ~2s, never a hang or a 500. → `osclient.Classify` unit tests (Task 2) + handler tests (Task 5) + a live check (Task 7).
2. **A delete or upsert while the alias is missing**, for example after someone deletes the index. OpenSearch auto-creates a plain index called `products` on a write to a missing name. After that, the alias can never be created, and the service is stuck until someone deletes it by hand. Expected: the write fails (503/500) and no index appears. → integration test in Task 3.
3. **Deep paging and silly ranges:** `page*size > 10000` or `minPrice > maxPrice`. Expected: 400 with a clear message, not a 500 from OpenSearch. → `query.ParseParams` table tests (Task 4).
4. **Query text with search syntax** (`phone OR (`, `"`, `*`, `\`). Expected: 200, treated as plain words. `multi_match` doesn't parse query syntax; `query_string` would, and must not be used. → builder test (Task 4) + integration test (Task 5).
5. **A bulk batch with one bad item**, such as a missing field, an id over 512 bytes, an `updatedAt` before 1970, or a value OpenSearch rejects. Expected: 200, the good items indexed, and the bad one in `failed` with its own status and reason. OpenSearch validates the **whole** bulk request before running it, so one item with a bad id or a negative version would reject the entire batch with 400. `Validate` must catch those first. → unit test (Task 3) + integration test (Task 3).

## Resolved questions (user, 2026-10-22)
- **opensearch-go v5**, not v4. ADR-0005 (Proposed); spec updated.
- **Facets count only the filtered results.** There is no `post_filter`.
- **Price buckets** (cents), one constant: `*–10000`, `10000–50000`, `50000–200000`, `200000–1000000`, `1000000–*`. `from` is inclusive and `to` exclusive, matching `PriceBucket`.
- **Bulk:**
  - 200 + `{indexed, skipped, failed:[{id,status,reason}]}`
  - 400 for a malformed body
  - 503 when OpenSearch is unavailable

  Spec updated. This is a 1.4 follow-up: catalog-api's reindex must read `failed` and pass the failed ids on.
- **Module path:** `github.com/AbanobNageh/product-catalog/services/search-service`.
- **My calls, accepted with "the rest sounds good":**
  - delete is idempotent (204 even if missing)
  - size 1–100, default 20
  - `sort=relevance` with no `q` falls back to `newest`
  - an integration test behind a build tag
  - `testdata/sample-products.json`
  - Dockerfile in 1.3
  - "already exists" on startup counts as success
- **Planning calls I made (flag any you disagree with):**
  - **`version_type=external_gte`, not `external`.** The version is `updatedAt` in epoch ms. With `external` (strictly greater), a reindex of unchanged data reports every item as skipped. Two updates in the same millisecond would also lose the second one. With `external_gte`, equal versions overwrite, and only **older** versions are skipped.
  - **No `action.auto_create_index=false` in Compose**, which I had mentioned. The code must protect itself (Review Focus 2), and setting it in Compose would make that integration test pass even if the code were wrong. Part 2's manifests then don't depend on a cluster setting.
  - **Delete goes through `_bulk` with one delete action**, because the single-document delete API auto-creates a missing index. The reviewer reports that bulk deletes never auto-create; instead, the item comes back as 404 with `error.type: index_not_found_exception`. So:
    - a 404 item with **no** `error` (`result: "not_found"`) → success
    - a 404 item with `index_not_found_exception` → `ErrAliasMissing`

    `require_alias=true` is still set; it covers index actions. The Task 3 integration test checks this against the real server. If the server behaves differently, the fallback is to check `Indices.ExistsAlias` first, with a ledger ruling.
  - **The bulk body is `{"products":[…]}`**, not a bare array, so it can grow fields.
    - More than **1000** products per request → 400.
    - A body over **10 MB** (bulk) or **1 MB** (single PUT) → 413.
  - **Bulk validates each item.** An invalid product goes into `failed` with status 400 instead of rejecting the batch, matching the user's "per-product problems are reported per product".
  - **PUT returns 200 `{"result":"indexed"|"skipped"}`** so stale writes are visible with curl. The path id must equal the body id, or 400.
  - **Index settings:** 1 shard and 0 replicas (single node → green), and `"dynamic": "strict"`, so a document with an unmapped field is rejected instead of silently changing the mapping.
  - **`track_total_hits: true`**, so `total` is exact, not capped at 10,000.
  - **Facet sizes:** category 20, brand 50. The spec's seed has about 10 categories and about 30 brands.
  - **Sorting:** every sort ends with a tie-break on `id` (asc), so paging is stable.
  - **Startup:** `index.Ensure` is retried every 2s for up to **30s**, but only while the error is `ErrUnavailable`. Then exit 1 with a log line naming the URL. A non-transient error (such as a mapping rejected with 400) exits at once.
  - **Router:** ADR-0005 is reworded to match. Discovery is off and the default router stays on, because the only off-switch is a process-wide env var, and seed-only routing is harmless. This was the reviewer's recommendation, made before the user saw the plan.
  - **Commits:** none per task. The milestone is committed once, after approval at the close, as in 1.2. Each task ends with a checkpoint.

### Task 2: Product model, OpenSearch client, index setup and readiness

**Files:** `internal/catalog/product.go` (+ test), `internal/osclient/osclient.go` (+ test), `internal/index/index.go` (+ test, + `integration_test.go`). Run `go get github.com/opensearch-project/opensearch-go/v5@v5.1.1`.

**Interfaces:**
- Produces, in `catalog`:
  - `type Product struct` with JSON tags `id, sku, name, description, category, brand, priceCents, currency, stock, createdAt, updatedAt`. All are strings except `PriceCents`/`Stock int`, and `CreatedAt`/`UpdatedAt` are strings.
  - `func (p Product) Validate() error`:
    - non-empty `id, sku, name, category, brand, currency`
    - `id` at most **512 bytes** (OpenSearch's limit)
    - `0 ≤ priceCents ≤ 2147483647` and `0 ≤ stock ≤ 2147483647`
    - both dates parse as RFC 3339, and `updatedAt` isn't before 1970-01-01, so the version can't be negative

    `description` may be empty. One error lists every problem.
  - `func (p Product) Version() int64`: `UpdatedAt` parsed, in Unix ms. Callers convert it to the `*int` that `IndexParams.Version` takes: `new(int(p.Version()))`.
  - `type Doc struct`: snake_case JSON plus `InStock bool \`json:"in_stock"\``.
  - `func ToDoc(Product) Doc` and `func FromDoc(Doc) Product`.
- Produces, in `osclient`:
  - `func New(url string) (*opensearchapi.Client, error)`, with the config from Global Constraints
  - `var ErrUnavailable = errors.New("opensearch unavailable")`
  - `func StatusOf(resp *opensearch.Response, err error) int`: prefers `resp.StatusCode`, then a `*opensearch.StructError`'s `Status`, else 0. v5 errors often carry no typed status: HEAD calls return a plain `fmt.Errorf`, and non-JSON 5xx bodies give `StringError` or `ErrJSONUnmarshalBody`. So the status code must come from the response, which v5 returns alongside the error. For typed responses, use `x.Inspect().Response`.
  - `func Classify(resp *opensearch.Response, err error) error`: returns a wrapped `ErrUnavailable` for:
    - a network error (`net.Error`)
    - `context.DeadlineExceeded`
    - `opensearchtransport.ErrNoConnections`
    - `StatusOf` ≥ 500 or == 429

    Otherwise it returns `err` unchanged; nil for nil.
- Produces, in `index`:
  - `type Names struct { Index, Alias string }` and `var Default = Names{"products-v1", "products"}`
  - `func Body(alias string) []byte`: settings, mappings and `"aliases": {alias: {}}`, so the index and alias are created in one atomic call
  - `func Ensure(ctx, c *opensearchapi.Client, n Names) error`
  - `var ErrAliasMissing = errors.New("search alias missing")`
  - `func Ready(ctx, c, n) error`
  - `func WaitFor(ctx, try func(context.Context) error, every, max time.Duration) error`

## Follow-ups this plan creates (for 1.4)
- catalog-api's HTTP `SearchIndexer.bulkUpsert` must read `failed` and pass the ids back from `/admin/reindex`, instead of turning any failure into 503.
