# 5.4 Release: Plan

**Goal:** The docs describe the API as it is after Part 5, and `v1.1.0` is a tag that someone with only Docker can clone, start, seed and search with a key. The agent repo builds from it.

**Spec:** [docs/plan/agent-ready-api.md](../plan/agent-ready-api.md), section "5.4 Release". Versions were moved to 5.3, and the AGENTS.md "Commands" keys were done there too.

**No code changes, no ADR:** this milestone changes docs only. The version bump, the image tags and the keys all shipped in 5.3 (4176754).

## Decisions (the user's, 2026-10-25)
- **`v1.1.0` goes on the docs work commit.** That commit holds the release content. The close note comes one commit later, the same way `v1.0.0` (245789e) sits before 5.1's notes.
- **The README quick start seeds through `docker compose run`.** It needs only Docker: no Node, no `npm ci`, no `.env`. The agent repo will run it the same way.
- **The clean-clone check runs as its own Compose project.** First `docker compose stop` on the running stack, which keeps its data. Then `-p catalog-v110` from a clone in the scratchpad, then `down -v` on that project only, then `docker compose start` on the user's stack.

- Image tags: `catalog-api:0.2.0`, `catalog-api-migrate:0.2.0`, `search-service:0.2.0`. Chart: `0.3.0`.
- Every command added to the README is run once before the commit, and its output is checked.
- The milestone notes, the ADRs and `docs/research/` are frozen. `docs/plan/kubernetes.md`'s `0.1.1` and `app.md`'s 1.5 Done-when are history, so they stay.
- Pushing needs the user's yes in that moment.

## Task 1: `docs/plan/app.md` (user-owned: the text below is the proposal)
Apply it only after the user approves it. The approval of this plan counts, unless the user changes the text.

1. **Line 25.** Replace `- **No auth, no frontend.** Swagger UI on catalog-api is the UI.` with:
   ```markdown
   - **No frontend.** Swagger UI on catalog-api is the UI.
   - **API keys with three scopes** (Part 5, [ADR-0020](../adr/0020-api-keys-with-scopes.md)): every catalog-api endpoint except `/healthz`, `/readyz` and `/docs` needs `Authorization: Bearer <key>`. search-service has no auth: only catalog-api can reach it.
   ```
2. **Data model:** a new row after `stock`:
   ```markdown
   | version | integer | starts at 1, +1 on every update; optimistic concurrency (Part 5, [ADR-0019](../adr/0019-optimistic-concurrency-with-if-match.md)) |
   ```
3. **catalog-api endpoint table:** a `scope` column, and the new parameters and headers:
   ```markdown
   Endpoints (Part 5, [agent-ready-api.md](agent-ready-api.md), added the scopes, `maxStock`, `stock_asc`, `version` and `If-Match`):

   | method | path | scope | what it does |
   |---|---|---|---|
   | POST | /products | write | create, then index (sync call to search-service); returns `ETag` |
   | GET | /products/:id | read | Redis cache-aside, TTL 5 minutes; returns `ETag: "<version>"` |
   | GET | /products?page&limit | read | list from Postgres, no cache |
   | PATCH | /products/:id | write | update, invalidate the cache, re-index; optional `If-Match: "<version>"`; returns the new `ETag` |
   | DELETE | /products/:id | admin | delete, invalidate the cache, remove from the index; optional `If-Match` |
   | GET | /products/search?q&category&brand&minPrice&maxPrice&maxStock&inStock&sort&page&size | read | proxies to search-service; caches results in Redis for 60s, keyed by the normalised query; any product write invalidates cached search results |
   | POST | /admin/reindex | admin | builds a fresh index from Postgres and swaps it in, while writes keep working ([ADR-0007](../adr/0007-alias-swap-reindex-with-live-writes.md)); 409 if one is already running |
   | GET | /healthz | none | liveness: the process is up (no dependency checks) |
   | GET | /readyz | none | readiness: Postgres and Redis reachable |
   ```
4. **The bullets under that table:**
   - `sort`: add `stock_asc` (stock, lowest first). Ties are ordered by `id`.
   - A new bullet: `maxStock`: only products with stock ≤ `maxStock` (`0`: out of stock only).
   - A new bullet: **Integer parameters** (`minPrice`, `maxPrice`, `maxStock`, `page`, `size`, `limit`) must be whole numbers within their bounds. A bad value gets one message: `<name> must be a whole number from <min> to <max>`.
   - A new bullet: **Keys:**
     - The scopes nest: `read` < `write` < `admin`.
     - A missing or unknown key gets 401 with `WWW-Authenticate: Bearer`.
     - A key with too low a scope gets 403, naming the scope that's needed.
   - A new bullet: **`If-Match`:**
     - It's optional.
     - Anything other than one strong ETag gets 400.
     - A stale version gets 412, with `currentVersion` in the body.
     - Search hits don't carry `version` (the index may be stale), so read the product with `GET /products/:id` before writing it.
5. **search-service table:** no change. "Same query params as above" now covers `maxStock` and `stock_asc`.
