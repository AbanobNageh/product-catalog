# 5.3 API keys with scopes: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every catalog-api endpoint except health and Swagger needs a key, and each key's scope (`read` < `write` < `admin`) limits what it can do. Every client and every environment is updated to send one. Released as catalog-api and search-service `0.2.0`.

**Architecture:**
- catalog-api has a global guard. Handlers declare `@RequireScope(...)` or `@Public()`. Keys come from three required environment variables and are compared by SHA-256 digest with `timingSafeEqual`.
- Clients get keys from: committed dev keys (Compose, `.env.example`, e2e); a Kubernetes Secret named by `catalogApi.apiKeysSecret`; and Terraform's `app` module, which generates the keys and creates that Secret before the release.
- This milestone also carries the 5.1 review's integer-parameter fixes, and the version bump moved here from 5.4.

**Tech Stack:** NestJS 12 (guards, `Reflector`, `@nestjs/swagger`), Node `crypto`, Helm 4 chart, Terraform 1.16 with `hashicorp/random` 3.9.1 (released 2026-09-11) and `hashicorp/kubernetes` 3.4, k6, kind.

**Spec:** [docs/plan/agent-ready-api.md](../plan/agent-ready-api.md), section "5.3 API keys with scopes". Design: [ADR-0020](../adr/0020-api-keys-with-scopes.md) (Proposed; accepted at the close).

## Global Constraints
- **Scopes:**
  - `read`: `GET /products`, `GET /products/:id`, `GET /products/search`.
  - `write`: `POST /products`, `PATCH /products/:id`.
  - `admin`: `DELETE /products/:id`, `POST /admin/reindex`.
  - Each scope includes the ones below it.
  - Open: `/healthz`, `/readyz`, `/docs`, `/docs-json`.
- **Header:** `Authorization: Bearer <key>`. The scheme is case-insensitive, and nothing else is accepted.
- **Errors:**
  - 401 for a missing, malformed or unknown key. Body: `{"statusCode":401,"message":"a valid API key is required: Authorization: Bearer <key>","error":"Unauthorized"}`, with the header `WWW-Authenticate: Bearer`.
  - 403 for a known key without the scope: `this endpoint needs the <needed> scope; your key has <has>`.
- **Config:** `READ_API_KEY`, `WRITE_API_KEY` and `ADMIN_API_KEY` are required, each at least 32 characters, and all different. Messages name the variable, never the value.
- **Dev keys** (committed, marked `# dev only, not secret`; each is 40 characters):
  - `READ_API_KEY=dev-read-key-not-secret-0000000000000000`
  - `WRITE_API_KEY=dev-write-key-not-secret-000000000000000`
  - `ADMIN_API_KEY=dev-admin-key-not-secret-000000000000000`
- **Integer query parameters** (`minPrice`, `maxPrice`, `maxStock`, `page`, `size` on search; `page`, `limit` on the list):
  - A bad value gets exactly one message: `<name> must be a whole number from <min> to <max>`, the same rule as search-service.
  - OpenAPI shows each as `type: integer` with `minimum` and `maximum`.
- **Versions:**
  - catalog-api `0.2.0` (`package.json` and `package-lock.json`) and search-service `0.2.0`.
  - Image tags `catalog-api:0.2.0`, `catalog-api-migrate:0.2.0` and `search-service:0.2.0`, in Compose, the chart's `values.yaml` and Terraform's `*_version` defaults (dev, staging, `aws/app`).
  - Chart `0.3.0`.
- **Terraform:**
  - `random` is pinned `~> 3.9` in each root, and `>= 3.9` in the module.
  - Keys: `random_password`, length 48, `special = false` (safe in headers and shell quoting).
  - The Secret is `catalog-api-keys`, created before the `helm_release`.
  - Outputs `read_api_key`, `write_api_key` and `admin_api_key`, all `sensitive = true`.
- **Who runs what:**
  - The user runs every `terraform apply`, the k6 load test, and the `helm`/`kubectl` commands that change a cluster.
  - The AI may run the free commands: `fmt`, `validate`, `init`, `plan`, `tflint`, `trivy`, `helm template` and `helm lint`.
  - Commits only with the user's yes, so they are proposed at the close.
- Swagger and the API change together; AGENTS.md "Commands" changes with every changed command. The T5 runbook lines in AGENTS.md (user-owned) change only in Task 6, which this plan's approval covers.

## Review Focus
1. **A route added later without a decorator must be closed, not open.** The guard refuses it, and a test walks the whole module graph, so a forgotten decorator fails CI. Test in Task 3.
2. **Header variations:** `bearer <key>` (lower case) must work. `Bearer` with no key, `Bearer  <key>` with two spaces, `Basic …`, a key with surrounding whitespace, and the right key with a different length must each be a 401, never a 500. `timingSafeEqual` throws on unequal lengths, which is why both sides are compared as digests. Test in Task 3.
3. **The seed against a keyed API:**
   - With `CATALOG_API_KEY` unset, the seed must exit 1 before inserting anything.
   - With a read key, catalog-api answers 403, and the seed exits 1 naming the admin scope.
   - Test in Task 4 (unit: the start check and the 401/403 mapping).
4. **A key must never reach a log or an error message.** That covers `loadConfig` errors, guard logs and seed logs. Tests in Tasks 2, 3 and 4 assert the key string is absent.
5. **The first apply on an existing cluster:**
   - The release must not start before the Secret exists (`depends_on`).
   - Upgrading dev from `0.1.1` to `0.2.0` must run the migration hook before the rollout.
   - Checked in Task 7 (the plan output and the order of events) and Task 8 (the hook log and `/healthz`).

### Task 1: integer query parameters (from the 5.1 review)

**Files:**
- Create: `services/catalog-api/src/common/int-query-param.ts`
- Test: `services/catalog-api/src/common/int-query-param.spec.ts`
- Modify: `services/catalog-api/src/products/dto/search-products.query.ts` and `list-products.query.ts`
- Test: `search-products.query.spec.ts`, `src/products/openapi.spec.ts`, `test/products.e2e-spec.ts` (the 5.1 messages)

**Interfaces:**
- Produces: `IntQueryParam(opts: { min: number; max: number; description?: string; example?: number; default?: number }): PropertyDecorator`. It combines:
  - `@ApiPropertyOptional({ type: 'integer', minimum, maximum, ... })`.
  - A single validator `IsIntInRange(min, max)` with the message `$property must be a whole number from <min> to <max>`.
  - The parser: blank means unset, plain digits with an optional leading `-` become a number, and anything else stays a string so the validator rejects it.
  - `page`, `size` and `limit` keep their defaults, and blank still uses the default.

- [ ] **Step 1: Write the failing tests**
  - `int-query-param.spec.ts`: one message for each of `-1`, `abc`, `1.5`, `1e3` and `2147483648`; `''` and `' '` stay unset; `'0'` gives 0.
  - `search-products.query.spec.ts`: in the invalid-value table, each case now has exactly one constraint, equal to the new message.
  - `openapi.spec.ts`: on `/products/search`, the query parameters `minPrice`, `maxPrice`, `maxStock`, `page` and `size` have `schema.type === 'integer'`, with `minimum` and `maximum` set. On `GET /products`, `page` and `limit` do too.
  - e2e (the 5.1 test): `maxStock=-1` → `message` equals `['maxStock must be a whole number from 0 to 2147483647']`, and the same for `abc`.
- [ ] **Step 2: Run them and see them fail**: `npm test`, then `npm run test:e2e`. Expected: FAIL (three messages, and `type: number`).
- [ ] **Step 3: Implement** `IntQueryParam` and use it on the seven parameters. `NotBelowMinPrice` and `WithinResultWindow` stay as they are.
- [ ] **Step 4: Verify**: `npx tsc --noEmit -p tsconfig.json`, `npm test`, `npm run lint` (no new warnings), `npm run test:e2e`. Expected: all pass.

### Task 3: the guard, the decorators and Swagger

**Files:**
- Create: `services/catalog-api/src/auth/auth.decorators.ts`, `api-key.guard.ts`, `auth.module.ts`
- Tests: `api-key.guard.spec.ts`, `src/auth/routes.spec.ts`
- Modify: `src/app.module.ts` (import `AuthModule`), `src/configure-app.ts` (`addBearerAuth()`), `products.controller.ts`, `admin.controller.ts`, `health.controller.ts`
- Test: `src/products/openapi.spec.ts`

**Interfaces:**
- Consumes: `AppConfig.apiKeys` and `Scope` (Task 2).
- Produces:
  - `RequireScope(scope: Scope)`: metadata, plus `@ApiBearerAuth()`, `@ApiUnauthorizedResponse()` and `@ApiForbiddenResponse()`.
  - `Public()`: metadata only.
  - `ApiKeyGuard`, registered as `APP_GUARD` in `AuthModule`.

- [ ] **Step 1: Write the failing tests**
  - `api-key.guard.spec.ts`, against a fake `ExecutionContext` (a request with headers, method and URL, and a response with `setHeader`):
    - `@Public()` passes without a header.
    - Each scope's key passes its own scope and every lower one, and each lower key gets 403 with the exact Global Constraints message.
    - `bearer <key>` passes.
    - 401, plus `setHeader('WWW-Authenticate', 'Bearer')`, for: no header, `Bearer`, `Bearer  <key>`, `Basic <key>`, ` <key>`, an unknown key, and the read key plus one character (Review Focus 2).
    - A handler with neither decorator gets 403 and logs at `error`.
    - The `warn` and `debug` logs never contain the key (Review Focus 4).
  - `routes.spec.ts`: walk `AppModule`'s module graph (each module's `imports` and `controllers` metadata). For every route handler (`path` metadata), expect a scope or `@Public()` on the method or the class, and expect the scope map in Global Constraints exactly (Review Focus 1).
  - `openapi.spec.ts`: the document has a `bearer` security scheme; keyed operations have `security` and a 401 and 403; `/healthz` has no `security`.
- [ ] **Step 2: Run, see them fail.**
- [ ] **Step 3: Implement.**
  - The guard reads metadata with `Reflector.getAllAndOverride` (handler, then class).
  - It parses `/^bearer ([^\s]+)$/i`.
  - It computes `sha256(key)` and compares it with all three precomputed digests with `timingSafeEqual`, without stopping at the first match.
  - Decorate every handler with the scope map, and put `@Public()` on `HealthController`.
- [ ] **Step 4: Verify**: `npx tsc --noEmit -p tsconfig.json`, `npm test`, `npm run lint`. Expected: all pass.
