# 1.5 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /admin/reindex` builds a fresh index and swaps it in atomically while product edits keep working. Reindex drops ghost products and takes seconds instead of ~21s. Images are tagged `0.1.0`, and the deferred 1.4 minors are fixed.

**Architecture:**
- **search-service:**
  - Package `index` gains the build lifecycle (start, current, finish, abort) and a startup guard that refuses a cluster that would auto-create `products*` indices.
  - Package `indexer` dual-writes each single-product write (build alias first, then live) and versions deletes.
  - Four new HTTP endpoints expose the lifecycle.
- **catalog-api:**
  - Orchestrates the reindex through a new `SearchReindexer` port.
  - Versions deletes from the deleted row's `updatedAt`.

**Tech Stack:** no new dependencies. Go standard library + `opensearch-go/v5`; NestJS 12 + Prisma 7.10.1 + Node 24 `fetch`. OpenSearch 3.9.0 (Compose).

**Spec:**
- [ADR-0007](../adr/0007-alias-swap-reindex-with-live-writes.md) (the design; read it first)
- [`docs/plan/app.md`](../plan/app.md): the search-service endpoints table and milestone 1.5's "Done when"

Follow-ups carried in: [1.4 note](2026-10-22-1.4-wire-up-compose.md#follow-ups).

**Branch:** `1.5-polish`, with one commit per task, squashed into one commit on `main` at close (`close-milestone`).

## Global Constraints
- **Names:**
  - live alias `products`
  - build alias `products-build`
  - concrete indices `products-v<n>`
  - `index.Default = Names{Index: "products-v1", Alias: "products", BuildAlias: "products-build"}`
- **Build index settings at creation:** the same mapping as `index.Body`, plus `"refresh_interval": "-1"` and `"gc_deletes": "10m"`. `FinishBuild` resets both to `null` (the defaults).
- **Abandoned build:** older than **10 minutes** by `index.creation_date`. The threshold is a parameter so tests can pass 0.
- **Auto-create guard:** Compose OpenSearch env `action.auto_create_index: "-products*,+*"`. Integration-test names move under the same prefix (`products-it-<hex>`), so one setting covers them. **Never** set the cluster setting from code.
- **Write order on dual-write:** the build alias **first**, then live. The build write never uses `refresh=wait_for`; the live write always does.
- **Every alias change is one `_aliases` call.** Finish and abort include `remove` of `products-build` from the named build index with `"must_exist": true`. *Amended in Task 2:* abort removes only the alias; `StartBuild` deletes every `<alias>-v<n>` index that has no alias, after numbering (ADR-0007 step 5).
- **Delete version (catalog-api):** `Math.max(Date.now(), row.updatedAt.getTime() + 1)`, from the row Prisma's `delete` returns. Sent as `DELETE /products/{id}?version=<ms>`. search-service requires it (400 if missing or not a positive integer).
- **Timeouts:**
  - search-service: build lifecycle calls **10s** (`bulkTimeout`); single writes stay **2s** per write.
  - catalog-api: reindex calls (start, bulk, finish, abort) use `bulkMs` **15000**; others stay **2000**. **No retries anywhere.**
- **Error contract:**
  - search-service: `ErrBuildRunning` and `ErrBuildGone` → **409** `{"error": ...}`. Abort of a gone build → **204** (idempotent).
  - catalog-api `/admin/reindex`:
    - 409 `"a reindex is already running"` at start
    - 409 `"the reindex was aborted or replaced; run it again"` mid-run
    - 503 when search-service is unavailable
    - 500 otherwise
- **OpenAPI is the contract:** every new status and field is annotated in the same task (`.claude/rules/services.md`).
- **Commands:** any changed run, test or build command goes into `AGENTS.md` **Commands** in the same task. Other AGENTS.md text is user-owned: propose, don't apply.
- **Never** run `docker compose down -v`, delete `products-v*` indices by hand, or touch `products-v1` from tests.

## Review Focus
1. **A build write fails** (for example the build index is write-blocked, or times out). Expected: the user's edit still returns 2xx and is in the live index, the build is aborted (index gone), and the running reindex's next call gets 409. → Task 3 `TestUpsertBuildFailureAbortsBuild`.
2. **No reindex running, and a product is deleted.** Expected: 204, and no index named `products-build` (or the test equivalent) appears. That's the auto-create trap from the ADR spike. → Task 3 `TestWritesWithoutBuildCreateNothing`.
3. **Two reindexes at once.** Expected: the second gets 409, and the first finishes normally. → Task 2 `TestStartWhileRunning`, Task 6 service test.
4. **A crashed reindex** (catalog-api killed mid-run). Expected: the next reindex gets 409 for up to 10 minutes, then takes over. The crashed run's later calls fail with 409 and can't touch the new build. → Task 2 `TestStartTakesOverStaleBuild`, `TestFinishWithStaleBuildName`.
5. **Write order: build before live.** It isn't deterministic in integration, so it's pinned with a recording fake OpenSearch. → Task 3 `TestDualWriteOrder`.

## Resolved questions (user, 2026-10-22)
- **Live edits stay allowed during reindex** (alias swap with dual-writes), not maintenance mode.
- **The auto-create guard:** infra sets the setting, and search-service checks it at startup (ADR-0007 option a).
- **The README moves** to the end of the project (`PLAN.md`); 1.5's "Done when" was rewritten (`app.md`).

**AI defaults (say if you disagree):**
- **The guard is a probe, not a settings parser.** At startup, send a versioned `_bulk` delete into the fixed missing index `products-autocreate-probe`:
  - `index_not_found_exception` means the cluster is guarded.
  - Anything else means it isn't: delete the probe index if it was created, and fail.

  This tests real behaviour, and OpenSearch's pattern rules (first match wins, `+`/`-`, wildcards) don't have to be re-implemented.
- **Test indices are renamed** `it-<hex>` → `products-it-<hex>`, instead of widening the cluster setting with a test-only pattern.
- **The Go DELETE stays 204** for both deleted and skipped (stale). catalog-api doesn't need the difference; it's logged.
- **`POST /products/_bulk`** (the 1.3 sample-data load) stays on the live alias with `wait_for` and doesn't dual-write.
- **catalog-api drops `SearchIndexer.bulkUpsert`.** Only reindex used it, and it now goes through `SearchReindexer.bulk`. The 1.4 "empty bulk response" minor moves to that method.
- **`/admin/reindex` result:** `{indexed, skipped, failed, swapped}`. If any item fails, it still returns 200, with `swapped: false` and the build aborted. The seed exits 1 when `swapped` is false.

### Task 6: catalog-api reindex orchestration, versioned remove, contract

**Files:** Modify `src/products/products.service.ts`, `products.service.spec.ts`, `admin.controller.ts`, `dto/search-result.response.ts`, `openapi.spec.ts`, `test/fake-search-service.ts`, `test/products.e2e-spec.ts`.

**Interfaces:**
- Consumes: Task 5 ports.
- Produces:
  - `ReindexResponse` gains `swapped: boolean` (documented in OpenAPI: "false when items failed; the old index is still live").
  - `ProductsService.reindex(): Promise<ReindexResponse>`

**Behaviour:**
- `remove`: `version = Math.max(Date.now(), row.updatedAt.getTime() + 1)`, from the deleted row; then `indexer.remove(id, version)`.
- **`reindex`:**
  1. `start`:
     - `SearchServiceError` with status 409 → `ConflictException('a reindex is already running')`
     - `SearchUnavailableError` → 503 (the existing message style)
  2. Page through Postgres as today, calling `reindexer.bulk(build, …)` per batch and summing.
  3. If `failed` is non-empty → `abort`, and return `swapped: false`. Otherwise `finish`, and return `swapped: true`.
  4. Any error after `start`:
     - best-effort `abort` (log, never mask the original error)
     - a 409 → `ConflictException('the reindex was aborted or replaced; run it again')`
     - unavailable → 503
     - otherwise rethrow
  5. `finally`: `cache.incr(SEARCH_VERSION_KEY)`, as today.
- `AdminController`: add `@ApiConflictResponse({ description: 'A reindex is already running, or this one was aborted or replaced' })`.

- [ ] **Step 1:** Write the tests in `products.service.spec.ts`:
  - `remove sends max(now, updatedAt + 1)`:
    - a fake clock (`jest.useFakeTimers().setSystemTime`) earlier than `updatedAt` → `updatedAt + 1`
