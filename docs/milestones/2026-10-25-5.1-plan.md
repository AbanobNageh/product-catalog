# 5.1 Stock filter and sort in search: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let search filter by `maxStock` and sort by `stock_asc`, so an agent can ask the server for low-stock products instead of paging through 10,000.

**Architecture:** search-service parses and validates the two parameters next to the price ones and adds a `range` filter and a sort to the OpenSearch body. catalog-api validates the same rules (its own 400) and forwards them; its forwarding (`toSearchParams`) and cache key (`searchCacheKey`) already loop over every field, so they only get tests.

**Tech Stack:** Go 1.26 (`net/http`, opensearch-go v5), NestJS 12 + class-validator, Jest, OpenSearch 3.9.

**Spec:** [docs/plan/agent-ready-api.md](../plan/agent-ready-api.md), section "5.1 Stock filter and sort in search".

## Global Constraints
- `maxStock`: a whole number from 0 to `MaxInt32` (2147483647), inclusive. Blank means unset. Inclusive upper bound (`lte`).
- `stock_asc`: `stock` ascending, then `id` ascending, like every other sort.
- `stock` is already an `integer` in the index mapping: no mapping change, no reindex.
- catalog-api returns its own 400 for a bad `maxStock` or `sort` (never a forwarded search-service error).
- Swagger changes in the same commit as the API change (`.claude/rules/services.md`). No new libraries.
- Versions stay as they are (0.1.1 / 0.1.0): the version bump is 5.4. `docs/plan/app.md`'s endpoint table is updated at 5.4 (user-owned).

## Review Focus
1. **`maxStock=0`** (a falsy value) must mean "only out-of-stock products", not "no filter": forwarded as `maxStock=0`, kept in the cache key, and built as `lte: 0`. Tests in Task 1 (build) and Task 2 (forwarding, cache key).
2. **`maxStock` with `inStock=true`:** both filters apply (stock 1..N). Test in Task 1 (integration).
3. **`stock_asc` with a text query `q`:** sorts by stock, not relevance (`sortFor` only replaces relevance when there is no `q`). Test in Task 1 (build).
4. **A blank `maxStock=` or `maxStock=%20`:** unset in both services, not 0 and not an error. Tests in Task 1 and Task 2.
5. **A different `maxStock` must not hit another query's cache entry:** `maxStock=5` and no `maxStock` get different keys. Test in Task 2.
