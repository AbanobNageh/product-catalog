# 1.2 catalog-api Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A NestJS catalog-api with product CRUD on Postgres (Prisma), Redis cache-aside, Swagger, health endpoints and graceful shutdown. Search and reindex go through stubbed search ports until 1.3–1.4.

**Architecture:** One Nest app in `services/catalog-api`. A `products` module owns CRUD, cache-aside, search proxying and reindex. It depends only on small infrastructure modules (`config`, `prisma`, `redis`) and on two ports from `search` (`SearchIndexer`, `SearchClient`), which are bound to stubs in this milestone. Postgres and Redis run in Compose. The app runs on the host for development, and from its own multi-stage image.

**Tech Stack (exact pins, see [ADR-0004](../adr/0004-version-pins-nest12-prisma7-ts6.md)):** Node 24 · NestJS 12.2 (`@nestjs/{core,common,platform-express,testing}` 12.2.0, `@nestjs/swagger` 12.0.2, `@nestjs/cli`/`schematics` 12.0.10), **CommonJS** · TypeScript **6.0.3** (not 7; swagger peers `^5.5 || ^6`) · `prisma` / `@prisma/client` / `@prisma/adapter-pg` **7.10.1 exactly** (npm `latest` for `prisma` is an 8.0 RC) · `pg` 8.23 · `redis` (node-redis) 6.3 · `class-validator` 0.15 · `class-transformer` 0.5 · Jest 30 + supertest 7 · images `postgres:18-alpine`, `redis:8-alpine`, `node:24-alpine`.

**Spec:** [`docs/plan/app.md`](../plan/app.md) (sections: Data model, catalog-api, Requirements for both services, milestone 1.2). Indexing contract: [ADR-0001](../adr/0001-two-services-synchronous-indexing.md). ORM: [ADR-0003](../adr/0003-prisma-as-orm.md).

## Global Constraints
- All config from env vars: `PORT` (default 3000), `DATABASE_URL`, `REDIS_URL`, `SEARCH_SERVICE_URL` (optional until 1.4), `LOG_LEVEL` (default `log`). No config files in the image. `.env` is loaded only if present, via Node's built-in `process.loadEnvFile()` (no `dotenv`).
- Structured JSON logs to stdout: `new ConsoleLogger({ json: true, logLevels })`. No logging library.
- Graceful shutdown on SIGTERM: stop accepting, drain in-flight requests, close Prisma and Redis, exit **within 10s** (hard-exit timer as a backstop).
- `/healthz`: liveness, no dependency checks. `/readyz`: Postgres and Redis reachable, otherwise 503.
- Migrations run as a separate command (`npm run migrate` = `prisma migrate deploy`), **never at startup**.
- Every index call goes through `SearchIndexer` (`upsert`, `remove`, `bulkUpsert`). No retries. A failed index call is logged, and the write still succeeds.
- Search unavailable → `503` with a clear message.
- Cache: `product:{id}` TTL **300s**. Search results TTL **60s**, keyed by `search:v<version>:<normalised query>`, and every product write bumps `search:version`.
- Multi-stage Dockerfile, `node:24-alpine` runtime, production deps only, non-root.
- No libraries beyond this list without asking. Notably: no Terminus, no `@nestjs/config`, no `dotenv`, no cache-manager.
- API JSON is camelCase (`priceCents`), and DB columns are snake_case (`price_cents`) via Prisma `@map`.
- Every run/test/migrate command added → update **Commands** in `AGENTS.md` in the same task.

## Review Focus
1. **`GET /products/search` shadowed by `GET /products/:id`.** With `:id` declared first, "search" fails UUID parsing with a 400. Expected: the search route wins. → e2e test in Task 6.
2. **Redis down or slow.** node-redis queues commands while it reconnects, so `GET /products/:id` would hang. Expected: the cache is bypassed, the product is served from Postgres and a warning is logged, while `/readyz` returns 503. → `disableOfflineQueue: true` + connect timeout, unit test in Task 3, service test in Task 5.
3. **Duplicate `sku`** on create or update. Expected: 409, not 500. → Task 5 unit test, Task 6 e2e.
4. **Bad or unknown ids.** A non-UUID → 400. An unknown UUID on GET/PATCH/DELETE → 404 (Prisma `P2025`), not 500. → Task 5.
5. **Bad bodies:** negative `stock`/`priceCents`, a fractional price (`19.99`), unknown fields, an empty PATCH. Expected: 400 from the DTOs, with DB `CHECK` constraints as a backstop. → Task 5 DTO tests, Task 2 migration.

## Resolved questions (user, 2026-10-21)
- `minPrice`/`maxPrice` are **cents**. Added to the spec.
- **Product writes invalidate cached search results.** Added to the spec. How: a counter key `search:version` goes into every search cache key (`search:v<n>:…`). Each create, update, delete and reindex runs `INCR search:version`, so old entries become unreachable and expire through their 60s TTL. This avoids `SCAN`/`DEL` over a keyspace. If the version can't be read (Redis down), search skips the cache entirely rather than risk serving stale results.
- Execution: **native** (superpowers:executing-plans). Commits: none per task. The milestone is committed once, after the user approves at the close (`close-milestone` step 4). Each task ends with a checkpoint instead.
