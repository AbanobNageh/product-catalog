# 5.2 Optimistic concurrency (`If-Match`)
- Date: 2026-10-25 · Commits: 8e0af1e, 410fcab · Plan: [2026-10-25-5.2-plan.md](2026-10-25-5.2-plan.md) · Design: [ADR-0019](../adr/0019-optimistic-concurrency-with-if-match.md)

## What was built
- **search-service:** a test only. `DecodeProduct` ignores the extra `version` field, so it never reaches the index, whose mapping is `dynamic: strict`. A temporary `version` field on `Product` made the test fail, which showed it guards the right thing.
- **catalog-api:**
  - Migration `20261025164752_product_version`: `ALTER TABLE "products" ADD COLUMN "version" INTEGER NOT NULL DEFAULT 1`.
  - `ProductResponse.version`, and a strong `ETag: "<version>"` on `GET`, `POST` and `PATCH /products/:id`. The controller sets it, and Express keeps it instead of generating its weak body-hash ETag. Express still answers `If-None-Match` with a 304, now based on the version.
  - `src/products/if-match.ts`: `parseIfMatch` accepts exactly one strong ETag `"1"` to `"2147483647"`, with surrounding whitespace allowed. Anything else (`*`, `W/"3"`, a list, a bare `3`) gets a 400 naming the format. `etag()` builds the header.
  - `ProductsService.update(id, dto, expectedVersion?)` and `remove(id, expectedVersion?)`:
    - Every update increments `version`.
    - An expected version goes into the query's `WHERE` clause, so the check and the write are one statement.
    - When no row matches (Prisma P2025), one more read tells 404 (gone) from 412 (changed). The 412 body is `{statusCode, message, error, currentVersion}`, and the 412 also drops the cached product.
    - Without an expected version, P2025 is still a plain 404.
  - A product cached in Redis before this release has no `version`, so it counts as a cache miss.
  - `SearchHit` / `SearchHitResponse`: a product without `version`, used for search hits.
  - The index-delete timestamp is renamed `indexVersion` in catalog-api. search-service's `?version=` is unchanged.
  - Swagger documents:
    - the optional `If-Match` header
    - the 412, with a `PreconditionFailedResponse` schema
    - the `ETag` response header
    - the retry rule ("re-read the product: your first attempt may have succeeded")
    - "search hits may be stale: read GET /products/:id before writing"
- **Tests.** Every new test was seen failing before the code that makes it pass.
  - Unit:
    - `if-match.spec.ts`: 16 cases, including Express's own weak hash.
    - Conditional update and delete: match, mismatch, missing, an empty body with a version.
    - The versionless cache entry.
    - The OpenAPI document: the header, the 412 and its schema, the ETag header, and that search hits have no `version`.
  - An e2e scenario: create (`ETag "1"`), conditional PATCH, stale PATCH (412 with the exact body), unchanged after the 412, PATCH without `If-Match`, weak ETag (400), a 409 that doesn't use up the version, a 304, stale DELETE (412), DELETE, a second DELETE (404), and `If-Match` on a random id (404).
  - catalog-api: 208 unit tests and 3 e2e tests.
- **Verified (Done-when), 2026-10-25, on the rebuilt Compose stack:**
  - Client A read `"1"`. Client B updated it with `If-Match: "1"` (200). A's update with `"1"` then got 412 with `currentVersion: 2`, and the product kept B's values.
  - A re-read `"2"`, and its update got 200 with `ETag "3"`.
  - A PATCH without `If-Match` got 200, and the version went to 4.
  - Untouched rows have version 1, and search hits have no `version`.
  - A versionless entry planted in Redis by hand was ignored. A stale entry planted by hand was dropped by the 412, so the re-read got the real version.
  - Compose's migrate step found both migrations and had nothing pending: generating the migration had already applied it to the dev database. The 5.4 upgrade on dev checks the migration hook.

## Decisions
- [ADR-0019](../adr/0019-optimistic-concurrency-with-if-match.md), accepted at this close.
- **The user's choices** (2026-10-25):
  - `If-Match` is optional, not required with a 428.
  - The existing index timestamp is renamed `indexVersion`.
  - Anything but one strong ETag gets a 400, instead of RFC 9110's full rules.
  - "Native" execution: the AI implemented every task, then a fresh reviewer checked the whole change.
- **Found while designing:** Express already sent a weak body-hash ETag on every response. Our strong ETag replaces it on the product endpoints. A weak ETag copied back into `If-Match` gets a clear 400.
- **Rulings the AI made during the build** (from its ledger):
  - The migration was generated against Compose's dev database, so it was already applied there.
  - An inline lint exception, with its reason, for `{ ...dto, version: { increment: 1 } }`. Dropping the DTO's prototype is intended, because Prisma needs a plain object. It's the first disable comment in hand-written code.
  - A malformed `If-Match` is checked before the database, like a bad UUID, so it's a 400 even for a missing product.
  - After the review: a stale DELETE now drops the cached product. The plan's Review Focus 5 had said a stale DELETE leaves the cache untouched. Dropping it only forces a fresh read; the product, the index and the search version stay untouched.

## Review findings and corrections
- **The fresh reviewer** (a separate AI agent, read-only) said ready to merge. It tested the race live: 8 rounds of 25 concurrent PATCHes with the same `If-Match` gave exactly one 200 each, plus DELETE-vs-PATCH races.
- **Its two Minor findings, which the AI re-graded Important by their effect on an agent and fixed test-first:**
  1. **A 412 loop on a stale cached copy.** If the cache delete after a write failed, or a read raced the write, `GET` could keep serving the old ETag for up to 5 minutes. An agent following the documented "re-read" advice would get a 412 again. Fix: the 412 drops `product:<id>`. Verified live with a stale entry planted by hand.
  2. **The 412 body wasn't in OpenAPI**, so `currentVersion`, the field an agent needs, was only in prose. Fix: a `PreconditionFailedResponse` schema on both 412s.
- **The user tested the milestone and asked for no corrections.** The user accepted ADR-0019 by approving the close.

## Follow-ups
- **5.4, AGENTS.md examples:** PowerShell 5.1's `curl.exe` strips the inner quotes of `-H 'If-Match: "3"'`, so the server sees `3` and answers 400. Write `-H 'If-Match: \"3\"'`. The reviewer found this live.
- **5.4:** check the migration hook on an upgrade of a running dev environment (already in the plan).
- **Rolling upgrades:** while old pods run, they update rows without incrementing `version` (ADR-0019, Consequences).
