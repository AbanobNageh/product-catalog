## What was built
Before writing anything, the AI explained the T5 concepts:
- the AWS provider, credentials and named profiles, IAM Identity Center (SSO) vs long-lived keys
- community modules (`terraform-aws-modules/vpc` and `/eks`) as versioned packages, like T3's local modules
- the cost model (pay per hour while a resource exists) and the two checkers, `tflint` and `trivy config`

The user made 16 design choices in three rounds (ADR-0017, ADR-0018); the AI wrote every file and checked current versions and prices before each round (Terraform Registry API, `aws` CLI lookups of engine versions and add-ons, the AWS Price List API). The user set up the account side and ran every apply and destroy.

- **Account access (the user, in the console):** IAM Identity Center with AWS Organizations, an SSO user with the `AdministratorAccess` permission set (4-hour sessions), and the CLI profile `catalog-aws` (`aws configure sso`). The AWS CLI, tflint and trivy installed with winget.
- **`terraform/aws/bootstrap/`** (applied): the state bucket `product-catalog-tfstate-766345100621` (versioning, SSE-S3, Block Public Access, owner-enforced ownership, a TLS-only policy, a 90-day lifecycle rule) and the USD 10/month budget `product-catalog-monthly` (alerts at 50% and 100% actual, 100% forecast). First applied with local state, then `init -migrate-state` moved its state into the bucket it created (the chicken-and-egg problem solved by migrating). `allowed_account_ids` on the provider and the backend.
- **`terraform/aws/infra/`** (79 resources, plans only): a VPC over 2 AZs (private `/19`, public and isolated database `/24` subnets, one NAT gateway), EKS 1.37 with 2× t3.medium (AL2023, access entries only, five add-ons, no customer-managed KMS key), ECR ×3 (immutable tags, scan on push), RDS PostgreSQL 18 (`db.t4g.micro`, password managed in Secrets Manager), ElastiCache for Valkey 9.1 (TLS), OpenSearch Service 3.7 (VPC only, HTTPS), a security group per data service admitting only the node security group, the OpenSearch service-linked role, and the AWS Load Balancer Controller's IAM role (AWS's v3.6.2 policy, pinned in `policies/`) with an EKS Pod Identity association.
- **`terraform/aws/app/`** (new root, ADR-0018): finds the cluster, Valkey and OpenSearch with data sources; kubernetes and helm providers authenticated with `aws eks get-token`; the RDS CA bundle as a ConfigMap; `modules/platform` (Gateway API CRDs, the AWS Load Balancer Controller 3.6.2, Traefik behind a Network Load Balancer limited to `admin_cidrs`) and `modules/app` with `values-aws.yaml`.
- **Chart 0.2.0:** off-switches for the in-chart Postgres and Redis, `catalogApi.database.existingSecret`, `catalogApi.redisUrl`, extra CA certificates (`NODE_EXTRA_CA_CERTS`), an OpenSearch settings hook Job (ADR-0007's `action.auto_create_index` through `_cluster/settings`), an optional route hostname, `templates/validate.yaml`, and `values-aws.yaml`. `k8s/traefik/values-aws.yaml` layers the EKS settings over the kind ones (`null` deletes `hostPort` and `nodeSelector`).
- **`modules/platform` and `modules/app`:** AWS switches (`install_metrics_server`, Traefik extra values and source ranges, `aws_load_balancer_controller`, `create_namespace`, `extra_set`), each defaulting to the kind behaviour, with two `moved` blocks for the addresses that gained `count`.
- **Docs:** `docs/aws-architecture.md` (diagrams of where things live and who talks to whom, the security layers, every component with its kind equivalent and hourly cost), the paid-part plan (`2026-10-25-T5-paid-part-plan.md`), and the `terraform/aws/` commands plus a 9-step session runbook in `AGENTS.md`.

Verified:
- **Free checks, re-run at the close:** `fmt -check` and `validate` in all three roots; `tflint --recursive` (with the AWS ruleset 0.50.0) and `trivy config --exit-code 1` in all three: clean. `bootstrap/` `plan`: "No changes". `infra/` `plan`: 79 to add. `app/` `plan` needs a live cluster (it fails with "couldn't find resource" otherwise, as designed).
- **trivy ignores:** 13 accepted findings, each with `#trivy:ignore:<ID>` and its reason. A scan of a copy with the ignores stripped confirmed each one matches a real finding; two that matched nothing (`AWS-0050`, `AWS-0057`) were removed. trivy's Kubernetes scan of the EKS module's bundled example YAML (34 `KSV-*`) is skipped with `--misconfig-scanners terraform`.
- **Chart:** `helm lint --strict` for dev, staging and aws. Dev and staging render identically to chart 0.1.0 apart from one comment and the chart label (diffed against renders taken before the change). The AWS render passed a server-side dry run on the dev cluster in an empty namespace (12 objects; nothing created). The `DATABASE_URL` step was tested with a fake password full of URL-special characters: it came back intact through a dry-run Secret and the app's own `pg-connection-string`.
- **Dev and staging:** `plan` showed one in-place update (chart 0.1.0 → 0.2.0) and the two moves; the user applied both (release revision 2, pods restarted once, OpenSearch untouched); `plan` "No changes" afterwards.
- **The paid session (attempted, blocked):** the user's first `infra/` apply failed twice over. RDS rejected the database name `catalog` ("a reserved word for this engine"); it's now `product_catalog`, read by the runbook from a new output. The node group couldn't launch any EC2 instance: the account's "Running On-Demand Standard instances" quota is 0 vCPUs, and requesting an increase returns AccessDenied ("contact AWS Support"). The user found two older AWS cases about the account (a suspension warning and a credentials review, both awaiting AWS for 7 and 22 days) and opened an Account Reinstatement case. The user destroyed the partial stack the same day; the AI verified with direct `aws` calls that every VPC, subnet, security group, NAT gateway (state `deleted`), EKS, RDS, ElastiCache, OpenSearch, ECR, IAM and Secrets Manager resource was gone, with only the bootstrap budget and bucket left.

## Decisions
- [ADR-0017](../adr/0017-aws-account-state-and-managed-services.md) (proposed): SSO profile with AdministratorAccess, us-east-1, two roots (`bootstrap/` with its state migrated into its own bucket, `infra/`), a USD 10 budget in Terraform, managed OpenSearch (network-only access), ElastiCache for Valkey, the EKS API endpoint limited to the user's IP, 2× t3.medium on-demand, the RDS password in Secrets Manager.
- [ADR-0018](../adr/0018-deploying-to-eks.md) (proposed): a third root `app/` reusing the modules, the database Secret from one runbook command, the AWS Load Balancer Controller (EKS's built-in one is legacy), the app reachable from the user's IP only, the RDS CA bundle via `NODE_EXTRA_CA_CERTS`, the OpenSearch setting as a chart hook, and the teardown order (Traefik's Service first).
- Closed without the paid part (the user's call): the plan makes it optional, and it's blocked on AWS, not on the code.
