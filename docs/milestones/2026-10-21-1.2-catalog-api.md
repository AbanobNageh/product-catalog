# 1.2 catalog-api
- Date: 2026-10-21 · Commits: 803731c · Plan: [2026-10-21-1.2-plan.md](2026-10-21-1.2-plan.md)

## What was built
`services/catalog-api`, a NestJS 12 app (CommonJS), plus `docker-compose.yml` with Postgres 18 and Redis 8.
- **Products:** CRUD on Postgres via Prisma 7.10.1 and the `pg` driver adapter. The first migration adds hand-written `CHECK` constraints (`stock >= 0`, `price_cents >= 0`).
- **Cache-aside** on `GET /products/:id` (`product:<id>`, TTL 300s). Lists are not cached.
- **Search proxy and reindex:**
  - `GET /products/search` and `POST /admin/reindex` (keyset batches of 500) go through the ADR-0001 ports, `SearchIndexer` (`upsert`, `remove`, `bulkUpsert`) and `SearchClient`, bound to stubs until 1.4. Search returns 503 for now.
  - Search results are cached for 60s under `search:v<n>:<normalised query>`, and every write runs `INCR search:version`.
- **Operability:**
  - config from env only, validated, listing every problem at once
  - Nest's JSON `ConsoleLogger`
  - `/healthz` (no dependencies) and `/readyz` (Postgres + Redis, 2s each)
  - SIGTERM drains in-flight requests, with a 10s backstop
- **Validation:** `class-validator` DTOs, a whitelisting `ValidationPipe`, and Swagger at `/docs` with response classes for every endpoint.
- **Image:** a three-stage, non-root Dockerfile (build → prod-deps → runtime).
- **Tests:** 95 Jest unit tests and a lifecycle e2e test. The e2e uses `catalog_test` and Redis DB 1, and is non-destructive.
- **Verified live:**
  - CRUD on the host and inside the image
  - cache miss → hit → miss again after an update
  - Redis stopped (fails in 3 ms) and paused (1.0s per request)
  - shutdown: idle 0.3s; an in-flight request drains with a 200; a hung request is cut at 10.3s with exit code 1
  - `migrate deploy` creates a missing database on a fresh volume

## Decisions
- [ADR-0004](../adr/0004-version-pins-nest12-prisma7-ts6.md), accepted at this close:
  - NestJS 12 instead of the spec's 11.
  - `prisma`, `@prisma/client` and `@prisma/adapter-pg` pinned to exactly 7.10.1, because npm `latest` for the CLI (and Prisma's own update notice) point at an 8.0 RC.
  - TypeScript 6, because `@nestjs/swagger` 12 doesn't support 7.
  - Jest needs `--experimental-vm-modules` to load the ESM-only Nest 12 packages.
- **Spec answers from the user:**
  - `minPrice`/`maxPrice` are in cents.
  - Product writes invalidate cached searches.
  - Both were added to `docs/plan/app.md`.
- **Write order:** DB write → delete the product cache entry → index call → bump the search version. Bumping before the index call would let a concurrent search cache pre-write results under the new version.
- **Redis can't slow requests down.** The client uses `disableOfflineQueue`, has an `error` listener and doesn't await its connect. Every cache call has its own 500ms timeout (`withTimeout`). node-redis's `commandOptions.timeout` was tried and doesn't work for this: it's removed once a command reaches the socket.
- **Dockerfile `npm ci --omit=dev --omit=optional`:**
  - The Prisma CLI and TypeScript are optional peers of `@prisma/client`, so the lockfile marks them `devOptional`, and `--omit=dev` alone kept them.
  - Adding `--omit=optional` took `node_modules` from 426 to 173 MB.
- **The e2e setup is `prisma migrate deploy` only.** Prisma 7.10 refused `migrate reset` because it detected an AI agent and required the user's explicit consent. The AI did not supply that consent itself. It redesigned the setup to be non-destructive: unique data per run, cleanup by the test, and a guard that refuses any database whose name doesn't end in `_test`.
- **npm 11 install-script approvals** (`allowScripts`): the Prisma CLI and engines are approved and pinned. Scarf telemetry and two native-build fallbacks are denied.

## Review findings and corrections
**From the user:**
1. **Spec gaps, answered at plan review:** price filters are in cents, and writes invalidate the search cache. The second answer caught a real conflict: a 60s search cache would have broken 1.4's "price change visible in search within a second" check.
2. **Version choices:** the user approved moving to NestJS 12 and pinning Prisma 7, then accepted ADR-0004 at close.
3. **"Why isn't the Nest log coloured?"** JSON mode turns colours off by default, and ANSI codes would corrupt JSON in `kubectl logs`. This was a clarification. The user chose to keep plain JSON, so nothing changed.
4. **"Why three Dockerfile stages?"** The explanation covered dev-only build tools, a cacheable prod-deps layer that runs in parallel with the build, and a minimal runtime. The two-stage `npm prune` alternative was discussed. This was a clarification, and nothing changed.
5. **Scaffold dev tools** (oxlint, prettier) were outside the plan's library list. The user kept them, and `lint`/`format` were added to Commands.

**From the fresh-context AI review** (a separate reviewer over the whole change, before the user's check). All of these were fixed test-first:
1. `null` in a body (`PATCH {"name":null}`) passed validation and returned 500. It's now 400 (`PartialType(..., { skipNullProperties: false })`, `ValidateIf` on `currency`).
2. Integers above the Postgres int4 limit returned 500. They're now 400 (`@Max(INT4_MAX)`).
3. `?maxPrice=` (empty) became `0` and would silently filter to free products. Empty now means unset, and `1e3`/`0x10` are rejected.
4. A connected but unresponsive Redis would hang requests. The reviewer estimated 5–10s and suggested `commandOptions.timeout`. Live testing showed a **187s hang** and showed that the suggested option has no effect. Fixed with a per-call timeout: 1.0s per request with Redis paused.
5. The STATUS "Now" block was stale.

**Found by the AI while building:**
- `nest new` 12 scaffolds ESM + Vitest without asking, so it was converted by hand.
- The generated Prisma client's `.js` imports needed a Jest module mapper.
- Jest gives each test file its own copy of `process.env`, so `.env.test` is applied with `parseEnv`.
- Node's async pipe writes dropped the "shutdown timed out" log line, so the process now exits from the write callback.

## Follow-ups
- **1.3:**
  - Version index documents by `updatedAt` (`version_type=external`) so an older concurrent update can't win.
  - Use `refresh=wait_for` on single upserts so 1.4's "within a second" check holds.
  - `SearchResult` in `search.ports.ts` is the contract search-service implements.
- **1.4:**
  - The HTTP `SearchClient` must wrap network errors, timeouts and 5xx responses into `SearchUnavailableError`. Other errors currently surface as 500.
  - 2s timeout on search-service calls.
  - The seed script.
- **K3:** the migration image (the runtime image has no Prisma CLI, per ADR-0003), and `preStop`/readiness behaviour on rollout.
- **K6 failure drills:** Postgres has no connect or query timeout (pg-pool waits forever when the database is unreachable).
- **Deferred minors:**
  - Cache-aside stale-set race, and a `del` that fails during a Redis blip, can serve an old product for up to 300s (fix: delayed double delete).
  - The product cache key isn't lowercased.
  - Reindex reports Postgres failures as "search unavailable".
  - A startup config error prints a raw stack, not a JSON log line.
  - `minPrice > maxPrice` isn't rejected, and a whitespace-only `sku` passes.
  - `--omit=optional` could silently drop a future runtime optional dependency.
  - Lint `unbound-method` warnings in specs.
- **1.1 follow-up still open:** confirm with `/memory` that `.claude/rules/services.md` loads when `services/` files are edited. The AI did not observe its contents arriving in context during 1.2.
