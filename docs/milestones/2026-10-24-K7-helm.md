# K7 Helm
- Date: 2026-10-24 · Commits: 1a0a660

## What was built
The AI wrote the chart and explained Helm's template syntax from scratch, using the chart's own files, before anything ran. The user approved the four design choices up front, recreated the cluster, and ran every install, upgrade and rollback.

- **One chart, `charts/product-catalog`** (chart 0.1.0, Helm 4.3.1), installed as the release `product-catalog` in `catalog`:
  - `templates/catalog-api/`: ConfigMap, Deployment, Service, HPA, PDB, HTTPRoute, and the migration and seed Jobs as hooks.
  - `templates/search-service/`: Deployment, Service, PDB.
  - `templates/postgres/`: ConfigMap, Secret (from values, `b64enc`), headless Service, StatefulSet.
  - `templates/redis/`: Deployment, Service.
  - `templates/_helpers.tpl`: the label helpers (`selectorLabels`, `stableLabels`, `labels`) and the shared Postgres env block. `NOTES.txt` prints the checks and the rollback commands.
  - No `appVersion`: the chart deploys two apps that release separately. Each workload's `app.kubernetes.io/version` label carries its image tag.
- **`values.yaml`** holds image tags, replicas, autoscaling, PDBs, resources (ADR-0011 sizes), route, Postgres auth and storage, Redis `maxmemory`, and the OpenSearch subchart's values.
  - Environment-specific values have no default and use `required`: the Postgres password and the route hostname. A plain install without an environment file fails with a clear message.
- **`values-dev.yaml`** holds only what kind needs on top: the password, `catalog.localhost`, `seed.enabled: true`.
- **OpenSearch through the official chart** as a dependency: `opensearch` 3.9.0 from `opensearch-project/helm-charts`, OpenSearch 3.9.0, `condition: opensearch.enabled`.
  - `Chart.lock` is committed; the downloaded `charts/` folder is git-ignored and restored with `helm dependency build`.
  - The K4 names are kept through `fullnameOverride` and `masterService` (`search-service-opensearch-0`).
  - Also set: single-node, security plugin off, `action.auto_create_index`, ADR-0011 resources (including `initResources`), a 1Gi volume, an HTTP liveness probe.
  - The root `chown` init container (`busybox:latest`) is disabled.
- **The HPA is a switch:** `replicas` is left out of the Deployment while `catalogApi.autoscaling.enabled` is true. A `checksum/config` annotation rolls catalog-api's pods when its ConfigMap changes.
- **The old app manifests were removed** (`k8s/catalog-api`, `search-service`, `opensearch`, `postgres`, `redis`, `namespace.yaml`). `k8s/` now holds only the platform: the kind config, Traefik's values and Gateway, and metrics-server's values. The `AGENTS.md` cluster commands were rewritten for the chart.

Verified:
- **Before installing:**
  - `helm lint --strict` passed, and the rendered output passed `kubectl apply --dry-run=client --validate=strict`.
  - Without `values-dev.yaml`, both `required` messages fire.
  - `helm template` caught that a parent chart's `tcpSocket: null` doesn't delete the subchart's default probe handler: the probe would have had two handlers. A null in a `-f` file or `--set` does work; tested both. See the decisions.
- **Fresh cluster** (the user's go-ahead):
  - `kind delete/create`; images loaded with `--name catalog`.
  - The platform reinstalled: Gateway API CRDs v1.6.3, Traefik 42.1.3, Gateway `PROGRAMMED True`, metrics-server 3.14.0.
  - One `helm install … -f values-dev.yaml --set catalogApi.image.tag=0.1.0 --wait --timeout 15m` gave revision 1, deployed.
  - The timeline from `kubectl get pods -w`:
    - Postgres was ready at 2m35s (image pull), and catalog-api was ready seconds later.
    - OpenSearch was ready at 7m24s (the 1.2 GB pull).
    - search-service was ready at 8m04s, after 7 restarts in `CrashLoopBackOff` while it waited (see the follow-ups).
    - Then the post-install hooks ran in weight order: migrate (`20261021100029_init` applied), then seed (10,000 inserted; reindex `indexed 10000, failed [], swapped true`).
  - Checks: `/healthz` returned `{"status":"ok","version":"0.1.0"}`; `phone` returned 115 hits; `products-v2` was green with 10,000 docs; the HPA was at 2; three PDBs (ours plus the subchart's `maxUnavailable: 1`).
- **Upgrade:** `helm upgrade … --set catalogApi.image.tag=0.1.1 --wait` gave revision 2.
  - The pre-upgrade migrate Job was recreated with `catalog-api-migrate:0.1.1` before the rollout and logged `No pending migrations to apply`. The seed didn't rerun.
  - A `/healthz` loop showed 0.1.0 and 0.1.1 answering alternately for about 10s, then only 0.1.1, with no errors.
  - New ReplicaSet `f57cd6f74` (0.1.1) at 2; old `84d544fb56` (0.1.0) at 0.
- **Rollback:** `helm rollback product-catalog 1`, then `2`, gave revisions 3 and 4 (`Rollback to 1/2`).
  - The loop switched versions both ways with no errors.
  - No migrate Job ran (creation time unchanged).
  - The existing ReplicaSets were scaled back up, and their Deployment revisions moved to 3 and 4.
  - Each revision is a `sh.helm.release.v1.product-catalog.vN` Secret.
- **Done-when:** `helm install` on a fresh cluster brings up the whole app: **passed**. `helm upgrade --set …tag=…` rolls out a new version: **passed**, plus rollback.

## Decisions (link ADRs)
- **Labels and selectors under Helm:** `instance` = release name, selectors on `name` + `instance` + `component`; object names unchanged; stable labels only in `volumeClaimTemplates`: [ADR-0012](../adr/0012-helm-labels-and-selectors.md). This supersedes part of ADR-0008 and settles its "decide in K7" question.
- **The migration and seed Jobs are hooks:** migrate `post-install,pre-upgrade` (weight 0), seed `post-install` (weight 10, dev only), `before-hook-creation`, install with `--wait`: [ADR-0013](../adr/0013-migration-and-seed-as-helm-hooks.md).
- **Everything in one chart, including Postgres and Redis,** so one `helm install` brings up the app (the Done-when). Traefik, the Gateway, the Gateway API CRDs and metrics-server stay platform-side, as separate releases and files.
- **A fresh cluster instead of adopting the running objects.** Helm won't take over objects that `kubectl apply` created, and the new selectors are immutable. The only data lost was the seed, which the hook recreated.
- **The old app manifests were deleted** rather than kept next to the chart, so there is one source of truth. Git history and the K1–K6 notes keep them.
- **OpenSearch readiness stays the subchart's TCP check.** Replacing it needs a `null` that only works from `-f` or `--set`, so every environment file would have to carry it. On one node, the port opens a few seconds before the cluster is yellow, and search-service checks OpenSearch itself.

## Follow-ups
- **search-service crash-loops on a fresh install** (7 restarts in 8 minutes). It exits after 30s without OpenSearch, and the backoff then delays it about 40s after OpenSearch is ready. Fix in the chart (an init container that waits for OpenSearch) or in the app (retry forever; the user's call).
- **Secrets:**
  - The Postgres password is in the values, so it's stored in every release Secret (`helm get values` shows it).
  - Production would use an `existingSecret` value or External Secrets, plus a `values.schema.json` so bad values fail at install. K8/T5.
- **The subchart's leftovers:**
  - a long PVC name (`search-service-opensearch-search-service-opensearch-0`)
  - `component` = its StatefulSet name
  - its own PDB (`maxUnavailable: 1`, harmless with one pod)
- **Hook Jobs aren't release objects:** `helm uninstall` leaves `catalog-api-migrate` and `catalog-api-seed` behind.
- **Small renames on the fresh cluster:** the catalog-api Service port is now named `http` (was `api`); the Postgres PVC is `data-catalog-api-postgres-0`.
- **T2:** decide whether Terraform's Helm provider installs the platform releases and this chart.
- **T3:** environments as values files (`values-dev.yaml` vs a future `values-aws.yaml`).
- **T5:** `opensearch.enabled: false` + `searchService.opensearchUrl` for a managed OpenSearch. Postgres would need the same switch for RDS.
- **`AGENTS.md` "Who writes what"** still says the user writes Parts 2–3. Since K5, the AI writes (the user's choice). Propose an update at the Part 2 close.
- **Still carried:**
  - K8: `POST /admin/reindex` is public; TLS on `websecure`; an unexposed Traefik dashboard; the NetworkPolicy.
  - App: Redis in catalog-api's `/readyz`; search-service doesn't recover its index after OpenSearch loses data.
  - T5: re-size requests on real nodes.
